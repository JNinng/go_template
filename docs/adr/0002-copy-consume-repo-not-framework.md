# 模板消费 = 复制仓库落地，非框架、非生成器

新项目从模板诞生的方式是：复制仓库全部内容 + 改 `go.mod` module 名 + 全局替换 import 路径（DESIGN.md §1 五步清单）。落地后模板代码即为项目自有代码，可自由修改；模板对使用方式没有任何运行时约束。

配套推论：

- 模板不承诺公共 API 稳定性，不发布版本兼容说明——项目魔改无心理负担。
- 模板自有代码不 import 任何组件（引入只发生在装配点），依赖单向（ADR-0001）。

## Considered Options

- **模板作为可依赖 module（框架形态）**——拒绝：背上公共 API 稳定承诺与版本兼容矩阵，"使用简单"变成"升级复杂"；框架化与"模板复制后即普通项目"的定位冲突。
- **安装型生成器**（gonew 类工具或自研 init 生成器）——拒绝：复制本身已是确定性操作，生成器引入模板语法与渲染守卫等二阶问题，长期维护的是"生成器与产物的同步"而非交付价值。
